Where the report was wrong

The claims we checked against source code, READMEs and the GitHub API on 18 November 2026.

The report saidThe Razorpay Recurring UPI Kit is an MIT-licensed service that needs under 500 MB of RAM.
CheckedIt's an Apache-2.0 TypeScript library that runs inside your own app, and Tawn's API is in Go. Its README calls it alpha and "not production-hardened". It has 0 stars, and all its commits are from one day in June.
The report saidThe bridge listens for Billr's "invoice paid" webhook and copies the invoice into Zoho Books.
CheckedBillr sends no webhooks. Its API routes are auth, health, invoices, mcp, oauth, public, stripe and v1. The bridge would have to poll Billr instead.
The report saidVaultwarden is GPL-3.0, and Cal.com is AGPL-3.0.
CheckedVaultwarden is AGPL-3.0. The calcom/cal.com repo now redirects to calcom/cal.diy, which GitHub lists as MIT. We don't yet know what that change means.
The report saidSelf-hosting the CRM avoids liability under the DPDP Act.
InferenceTawn is the data fiduciary and is responsible wherever the data sits. Hosted processors are allowed under a contract. Owners' names and numbers are personal data either way.
The report saidRun Coolify, with one shared Postgres and one shared Redis for every app.
InferenceCoolify likes to run each app's database itself, so the two ideas pull against each other. Pick one: Coolify manages everything, or a plain compose file manages a shared database.

Risks to keep in view

GST on Billr invoices

Billr has no Indian GST format, so its PDFs alone aren't compliant invoices for Indian venues. Something else has to issue the official invoice.

Never collect Aadhaar

The report suggests encrypting Aadhaar or PAN. The Aadhaar Act restricts who may store Aadhaar, so don't collect it at all Inference.

AGPL

AGPL tools are fine internally. If people outside Tawn use a modified copy over the network, we must publish our changes. This covers Sellbird, Listmonk, Documenso, Plane and Vaultwarden.

Shared Redis

One Postgres server with a database per app is fine. Sharing one Redis is riskier: Sidekiq needs noeviction, and one app clearing its data can affect the others.

Product analytics gap

Plausible and Umami count website visits. Funnels and feature use in the venue app need something else, perhaps PostHog's hosted tier, since self-hosting it needs about 16 GB Report.

Not covered at all

Single sign-on across the tools, backups with a tested restore, one place for logs, and feature flags.
